### Bug intake

**Take a user report from words to a filed, evidence-backed issue.** Use when the user reports something broken and the deliverable is a GitHub issue.

Read first: ../qa-session/SKILL.md, ../qa-file/SKILL.md, ../qa-repro/SKILL.md

1. Run **qa-session**. Clarify with at most three questions. Explore the codebase in the background for domain language.
2. Run **qa-repro** on the clearest report. Capture the failure on video and the failure state in a screenshot.
3. Decide single issue or breakdown. Many thin issues beat one thick issue.
4. Run **qa-file** per issue, in dependency order, media attached.
5. Fresh-context review of each body when a spawn tool exists.

**Reply:** the issue URLs, blocking relationships as one line each, and the open questions if any.
