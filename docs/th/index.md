# เอกสาร QA Stack (ภาษาไทย)

QA ที่ยึดหลักฐานเป็นหลัก สำหรับ coding agent หนึ่งวงจรชีวิต:
รับรายงานบั๊ก ค้นข้อมูลอ้างอิงพร้อมแหล่งที่มา ทำซ้ำข้อผิดพลาด
พร้อมหลักฐานวิดีโอและภาพถ่าย วิเคราะห์สาเหตุที่แท้ เขียนสเปกพฤติกรรม
แบบ BDD บันทึก issue ที่ทนทาน พิสูจน์ว่าแก้ได้จริง และตัดสินปล่อยเวอร์ชัน

## สรุปภาษาไทย

### ติดตั้ง

```sh
npx skills add jirayusueb/qa-stack
```

แล้วรัน `/qa-setup` ครั้งเดียว ระบบจะตรวจ capability เรื่อง spawn,
issue tracker และ browser driver ให้อัตโนมัติ

### วงจรชีวิตบั๊ก

1. **Intake** (`/qa-session`) รับฟัง ถามไม่เกิน 3 ข้อ
2. **Ground** ค้นพฤติกรรมที่คาดหวังพร้อมแหล่งอ้างอิง
3. **Reproduce** (`/qa-repro`) กรณีเล็กที่สุด + วิดีโอ + ภาพถ่าย
4. **Diagnose** (`/qa-diagnose`) เปลี่ยนทีละตัวแปร
5. **Spec** (`/qa-bdd`) Gherkin ภาษาโดเมน อ้างอิงทุกข้อ
6. **File** (`/qa-file`) issue ทนทาน แนบหลักฐาน
7. **Fix-Verify** (`/qa-verify` → `/qa-regression`) พิสูจน์สองด้าน
8. **Gate** (`/qa-gate`) ตัดสิน go / no-go พร้อมเหตุผลอ้างอิง

แทร็กขนาน: `/qa-explore` ล่าบั๊กตาม charter, `/qa-ask` ตอบคำถาม
แบบอ่านอย่างเดียว

### หลักฐาน

ทุกข้อความต้องมีการอ้างอิง `[source-id]` พร้อมป้ายความมั่นใจ
`verified` / `reported` / `inferred` บั๊กที่มองเห็นต้องมีภาพถ่าย
บั๊กของ flow ต้องมีวิดีโอ ทุกไฟล์ต้องมีคำอธิบายกำกับ

### โหมดทำงาน

ทักษะเดียวกันรันได้ 3 แบบ: คนเดียว (solo), มี subagent ช่วย
review ด้วย context ใหม่ และ ทีม ที่แบ่ง write scope ไม่ทับกัน

หมายเหตุ: ถ้าเอกสารไทยกับอังกฤษขัดกัน ให้ถือตามฉบับอังกฤษ
